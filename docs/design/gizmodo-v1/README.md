# Gizmodo Japan 风格改版方案与设计初稿

版本：v1，2026-10-30。适用：本地会议、访谈音视频的批量转写、任务管理与后续查阅。

本次交付为设计方案、可点击初稿与预览图。应用业务代码和数据未改动；初稿不连接 ASR 服务，使用示例数据。

直接打开：[可点击初稿](prototype.html) · [结果库预览](01-library-desktop.png) · [任务中心预览](02-tasks-desktop.png) · [阅读页预览](03-reader-desktop.png)。初稿文件需与同目录下的 JS、CSS 和 assets 一起保留。

## 1. 设计结论

采用 Gizmodo Japan 当前站点的视觉语言：白色画布、黑色胶囊页头、宽体英文展示字、黑色结构线、荧光绿筛选标签、开放的主栏与侧栏，以及文章式阅读排版。

工作空间仍围绕「批次 → 文件任务 → 结果」组织。常用操作常驻；结果库借用媒体的浏览节奏，任务中心保留清单效率，结果详情借用文章的阅读层级。

### 参考核实

检查了 [首页](https://www.gizmodo.jp/)、桌面菜单、390px 手机首页、[文章页](https://www.gizmodo.jp/article/2610-mamoru-oshii-meta-mirai-ai-creative/)，并读取公开 CSS 与浏览器计算样式。以下数值是本次访问的观测，站点以后可能变化。

| 项目 | 参考站观测 | 在本项目中的对应 |
| --- | --- | --- |
| 英文展示字 | Special Gothic Expanded One，400 | 本地加载同一字体，用于品牌、栏目标题、少量日期 |
| 日文正文 | Hiragino Kaku Gothic ProN、YuGothic、Meiryo 等系统字体栈 | 换为中文系统黑体栈，避免日文字形与不受控的中文回退 |
| 主要颜色 | 白、黑、`#C9FE6E`、`#737373`、`#E5E5E5` | 保留主色关系，补充清楚的错误和警告语义色 |
| 桌面结构 | 1440px 视口下：页头 120px；内容主栏约 860px、侧栏 300px、间隔 40px | 页头压缩为约 88px；应用工作区采用弹性主栏与 272px 侧栏 |
| 文章层级 | h1 40px / 1.6 / 600；正文 16px / 2，正文内栏约 700px | 阅读标题 32–36px，正文 18px / 1.9，文字列约 680–740px |
| 控件外形 | 黑色胶囊品牌区、3px 黑边搜索框、绿色标签、粗黑分隔 | 用于全局头部、搜索、筛选和分区；任务行以细分隔为主 |
| 手机适配 | 页头约 70px，主栏单列，侧栏隐藏/下移 | 全局导航保留；批次与筛选可展开，关键状态继续可见 |

公开样式依据：[基础样式](https://www.gizmodo.jp/_next/static/css/9f3895412a306be7.css)、[内容样式](https://www.gizmodo.jp/_next/static/css/845874c7c775144c.css)。这些文件名是当前构建产物，不作为应用运行依赖。

参考站品牌标志是 SVG。初稿用本项目名称 Qwen ASR 重新排字，不使用 Gizmodo 标志、文章、照片或导航文案。

## 2. 全局 UI 规范

### 字体

| 用途 | 字体与规格 | 约束 |
| --- | --- | --- |
| 品牌 Qwen ASR | Special Gothic Expanded One，400，28–32px | 白字黑色胶囊；移动端 20–22px |
| Library / Tasks 等栏目字 | 同上，400，28–40px，行高 1.2 | 每页一个主要英文展示标题；中文说明维持清楚的导航语义 |
| 中文标题 | Microsoft YaHei / PingFang SC / Noto Sans CJK SC，600–700 | 大标题 32–36px，列表标题 15–16px，结果卡片 20px |
| 控件与文件信息 | 同中文栈，14px，行高 1.5 | 文件名不用等宽字；重要状态不低于 13px |
| 阅读正文 | 同中文栈，18px，行高 1.9 | 允许切换为字幕行；不强制首行缩进、两端对齐 |
| 时间码与技术数值 | Consolas / 项目现有 Geist Mono，12–14px | 使用 tabular-nums；不把整页都设成等宽字体 |

初稿实际本地包含 91,572 字节的展示字体及 [OFL 许可证](assets/OFL-SpecialGothicExpandedOne.txt)，无需外网。此字体只有展示用的 400 字重，不伪造多个展示字重。中文使用已有系统字体，微软雅黑文件不随项目重新分发。跨平台需要一致字形时，再增加经验证的 Noto Sans SC 本地字体包。

CSS 建议：

```css
--font-display: "Special Gothic Expanded One", Arial, sans-serif;
--font-ui: "Microsoft YaHei", "PingFang SC", "Noto Sans CJK SC", sans-serif;
--font-code: "Geist Mono", Consolas, monospace;
```

### 配色与形状

| Token | 值 | 用途 |
| --- | --- | --- |
| canvas / surface | `#FFFFFF` | 画布、正文与列表 |
| ink | `#000000` | 主文字、品牌、主操作、结构线 |
| accent | `#C9FE6E` | 选中筛选、搜索命中、当前处理的少量强调；搭配黑字 |
| text-secondary | `#737373` | 日期、来源等次要信息；小号重要文字用更深的 `#595959` |
| divider | `#E5E5E5` | 行分隔、非交互分区；控件轮廓使用更深的线或黑色 |
| surface-muted | `#F8F9F9` | 音频示意、非重点背景 |
| error | `#B91C32` | 错误文字，浅红底 `#FFF0F2` |
| warning | `#804A06` | 不完整结果，浅黄底 `#FFF2D8` |

- 绿色不等于“处理成功”。已完成用勾选图形与文字；错误和警告有独立形状、文字和颜色。
- 全局外壳约 36px 圆角；胶囊控件半高圆角；弹窗 20px；表格行无卡片阴影；图片/音频区域为直角。
- 结构线：栏目 3px 黑线，搜索与主要边框 2–3px，列表行 1px 灰线。避免每行都使用粗框。
- 间距采用 4/8/12/16/24/32/40/48px。阴影主要用于弹窗，正文和列表不叠玻璃背景。
- 动效以 120–180ms 的颜色和面板反馈为主，尊重减弱动效设置；任务进度不反复闪烁。

### 页面骨架

│                                           │                      │

│ Tasks：批次摘要、筛选、文件清单             │                      │

默认 1280×820 时，左右边距约 40px、侧栏 248–272px、栏间距 32px；1440px 时容器上限约 1320px，栏间距 40px。结果页页头约 88px，任务模式压缩为 68px；手机约 76px。小于 1100px 收起常驻侧栏；小于 680px 改为单列，搜索、批次与处理状态使用可展开区域。200% 缩放时允许重排。

### 对原站 UX 的调整

- 任务中心、结果库和新建操作常驻，更多菜单只放模型、存储、应用信息等低频项。
- 页头和大标题收紧，默认窗口中能看到实际文件与进度。展示字承担识别，正文空间优先。
- 排行榜位置用于批次、待处理异常、同批结果。没有广告位、阅读排行、社交分享和自动推荐流。
- 结果库有明确分页/加载更多，返回恢复位置；不把全部任务塞进不可追溯的无限滚动。
- 点击一份结果不会清空任务队列；新结果完成不会替换正在阅读的内容。

## 3. 各页面与交互

### 3.1 任务中心

主区显示批次名称、创建时间、完整/有缺失/失败/正在处理/等待数量，以及文件清单。侧栏提供批次切换、当前执行状态和异常入口。

每行保留：勾选、完整文件名、相对来源、时长（未知显示“待检测”）、处理状态、结果入口/重试。桌面行高约 56–64px，窄屏需要换行时增加。任务模式省去通用页脚，处理配置放侧栏，使默认窗口能看到更多文件；搜索筛选与表头固定，清单单独滚动。手机和过矮窗口采用整页滚动，避免裁掉操作。

- 文件名点击只打开已有结果；无结果时展示任务详情与错误说明。
- 查看排序与执行顺序分开。表头排序不改变 GPU 调度；调整执行顺序只操作等待项，并在完整队列视图中进行。
- 多选后出现统一操作栏，显示选中数、可导出数、可重试数。说明选择范围是否跨筛选、跨页。
- 暂停全部：先显示“当前文件完成后暂停”；真正停止后显示“继续处理”。取消当前文件单独命名，说明保留部分结果和重跑规则。
- 上传部分成功时逐项显示回执，重试只针对未提交项；不会因整体报错让用户重复提交已加入的文件。

批次结束显示总结，批次和结果继续存在。归档只收起入口；删除结果、移出待处理、清理音频分别操作。

### 3.2 结果库

借用媒体首页的标题、日期、分区和浏览节奏，重点服务“回来找某份会议/某句话”。

- 顶部展示继续阅读的一份结果：显示标题、原文件名、日期、上次位置及短摘录。摘录来自实际转写文本，不自动编造摘要。
- 最近结果采用开放式两列版面；用户可切换为紧凑列表，偏好保留。
- 搜索覆盖显示标题、原文件名、批次和正文关键词，命中显示上下文与时间码，点击直接定位。
- “会议/访谈”只在用户指定类型或来源明确时使用，未设置则属于未分类；“未查看/有缺失”可直接由记录推导。
- 未查看是该结果版本未打开过，不等于人工未校对；重新生成的版本重新计查看状态。
- 可多选导出，也可从批次导出。长文件名可换两行或显示来源，不能只靠 hover 辨认。

初稿中的波形是示意图形，说明媒体区域的视觉比例。当前后端没有波形/视频首帧接口；实现时先用清楚的文件类型面板作回退。只有读取真实音轨数据后才显示实际波形，不把示意图形当作音频信息。

### 3.3 结果阅读

沿用文章的标题、元数据、窄正文列和侧栏节奏；保留转写所需的时间定位与完整性提示。

- 顶部：返回原清单、显示标题、原文件与来源、处理日期、导出；模型/耗时/RTF 等放进详情。
- 正文：18px / 1.9，左侧时间码；支持文内关键词查找。时间码关联音频时可回听，未关联时说明原因。
- 不展示自动生成的说话人身份：当前后端没有说话人分离。访谈对象名称是用户设置的素材元数据。
- 段落阅读是对原始 segments 的显示分组，不改变保存的时间戳与字幕导出；字幕行视图继续保留。
- 缺失片段、取消后的部分结果、词级对齐回退使用明确提示，可定位缺失范围；不把完整性当作准确率评分。
- 右栏显示同批/同筛选结果、上一份/下一份；窄屏收为按钮。保持原筛选、滚动、查找内容、阅读与播放位置。
- 新任务完成只更新运行区与轻提示，播放器和阅读组件不得重建。部分结果也能打开，缺失媒体不会阻止文字查看。

### 3.4 统一导入

原生对话框，约 800–920px 宽，有清楚的标题和固定操作区；只保留一个内容滚动区域。

顺序：批次名 → 文件/文件夹选择 → 清单与排除原因 → 处理设置 → 提交说明。重要设置放在用户能看见的位置，清单很长时仍可展开确认。

- 各入口都先确认范围。单文件形成只有一项的批次；拖入时不会因为忙闲而悄悄改变语义。
- 多次选择累加；不同目录的同名同大小文件分别保留。不凭“文件名+大小”自动判定相同内容。
- 明确总发现数、已选数、排除数；逐项取消选择。暂存容量、数量和文件大小限制从后端读取，不继续在 UI 里维护另一套配置。
- 词级时间戳默认沿用上次设置；不可用时说明实际回退。语种和模型显示实际生效值，仅开放已经能兑现的覆盖项。
- 当前空闲时按钮为“开始处理 N 个文件”；忙碌时为“加入待处理 · N 个文件”；暂停时说明导入后仍需恢复队列。

### 3.5 导出、设置、启动与空状态

| 场景 | 设计 |
| --- | --- |
| 导出 | SRT 默认，保留 VTT/ASS/TXT/JSON；多文件一次 ZIP，默认只含完整结果，部分结果需显式勾选；包内含范围与异常清单 |
| 同名导出 | 保留源相对目录；跨来源冲突添加稳定后缀，不覆盖 |
| 导出回执 | 只在生成下载成功后记录；浏览器不声称已经保存到用户某路径 |
| 模型与性能 | 更多菜单进入；显示模型、对齐后端、可用状态。后端模型切换入口可在后续接入，运行中明确限制 |
| 存储 | 文字记录与回听音频分开说明。清理音频显示释放空间与回听影响，不混在清空历史中 |
| 启动 | 同一黑白绿色语言显示准备阶段与可重试错误；已有任务/结果时恢复工作空间，不强制弹上传窗口 |
| 首次空白 | 直接说明可以导入文件或文件夹，主操作“新建转写”；不显示空统计卡片墙 |
| 查询无结果 | 保留关键词和筛选，给出清除筛选入口；不自动重置用户条件 |
| 退出 | 桌面关窗当前会停止后端，明确下次重开中断文件从头处理；浏览器关标签与退出桌面应用区分 |

## 4. 状态与数据要求

UI 中的“正在处理”与“正在查看”是独立状态。

| 处理状态 | 结果可用性 | 界面表达 |
| --- | --- | --- |
| queued / running | 无可用结果或仅处理中的片段 | 等待处理 / 准备音轨 / 转写 / 生成时间戳 / 保存 |
| done | 完整结果已成功持久化 | 已完成，可查看/导出 |
| done + chunk_failures | 其他片段可用 | 已完成，有缺失；展示缺失范围 |
| done + alignment fallback | 文本可用，实际段级时间戳 | 时间戳回退提示，不谎称词级对齐已启用 |
| error | 没有可用结果 | 原因、影响、针对性的重试或重新选择文件 |
| cancelled | 可有部分结果 | 已取消，有部分结果 / 已取消，无结果 |
| 保存失败 | 结果暂可读但未持久化 | 明确提示保存失败，不能计入可长期回访的成功数 |

最少需要：batch_id、稳定 task_id、原始文件名/相对路径、用户显示标题、可选会议日期/访谈对象、执行配置快照、结果版本、完整性、缺失范围、首次查看时间、阅读/播放位置、媒体实际可用性和导出生成时间。

会议发生时间与结果生成时间分开，不用文件修改时间推断会议日期。旧结果进入“未分组的历史记录”，旧队列归入“升级前队列”；不猜测过去的批次。队列清理后仍保留批次与结果关系。

## 6. 实施顺序与验收

1. **视觉基础与阅读隔离**：字体/token/AppShell；执行状态与阅读分开；消除自动换结果；把缺失/回退/保存失败表达清楚。
2. **批次工作空间**：批次与任务持久化、统一导入、任务清单、返回上下文；定义取消和来源保留策略。
3. **结果库与交付**：基础正文查询、命中定位、查看位置、多选 ZIP 与清单；旧记录迁移与分页。
4. **可选增强**：真实音频波形/视频缩略图、高级检索、人工审核、完整版本比较、托盘后台运行和片段续跑。

验收重点：

- 1280×820 能看到主要任务和操作；960px、390px 与 200% 缩放不出现页面横向溢出；主要触控操作区约 44px，紧凑标签维持足够间隔和可见焦点。
- 同名不同目录不会静默丢失，部分提交成功后不会重复入队，排序不影响调度。
- 读 A 时 B 完成，不改变 A 的正文、查找、滚动和音频状态；返回恢复清单上下文。
- 暂停等当前文件完成；中断重启只重跑未完成文件，并准确说明不是片段续跑。
- 取消后的部分结果可打开；不完整结果默认不混入完整导出；失败项不会被完成清理顺带删除。
- 媒体缺失时文字可读；超过 200 份记录后早期结果仍可查。
- 键盘可完成导航、筛选、导入和导出；对话框管理焦点并支持 Escape；状态不只靠颜色。
- 正常文字对比至少 4.5:1，控件边界与焦点满足相应对比要求；绿色用于黑字，不配白色细字。
- 不为每条任务轮询完整字幕；本地字体加载失败仍可操作；渲染不依赖 Google Fonts 或外部 CDN。

## 7. 初稿使用与边界

双击 [prototype.html](prototype.html)。主要页面：结果库、任务中心、结果阅读；对话框包括新建批次、导出与更多设置。顶部独立的示例工具可模拟完成一项任务，验证阅读不会被切换。

可验证：搜索/筛选、同批切换、查看标记、返回上下文、暂停/恢复、重试、导入逐项选择、同名来源区分、导出范围及部分结果确认。

字体是真实本地文件，波形与转写是原创示例。刷新页面恢复示例数据；不会保存真实文件内容。续读时间采用固定示例，未接入真实阅读/播放进度保存。真实 ASR、持久化、音轨定位、ZIP 文件生成、删除与模型切换须在接入业务时验证；初稿中的说明不等于这些后端能力已经完成。
